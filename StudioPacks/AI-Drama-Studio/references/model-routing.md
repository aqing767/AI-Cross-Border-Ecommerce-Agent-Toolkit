# 模型路由：能力优先，不按品牌猜

## 能力快照

每个项目开始和每次重大模型更新时，记录：
- provider、精确 model_id、入口 / endpoint；
- status：verified / unverified / unavailable；
- 输入类型、参考素材类型与数量上限；
- 单次时长、画幅、分辨率、帧率、音频能力；
- prompt 字数 / token 上限；
- 异步任务、轮询、collect / retry 能力；
- 计费单位、价格来源和核验日期；
- 上传可见性、保存期限和删除方式；
- 官方文档链接或真实 probe 记录。

未验证的能力不用于批量生产。先做低成本 probe，再记录实际行为。

## 选择顺序

1. 先定义画面需求：身份锁、空间、动作、对白、时长、声音、编辑或续写。
2. 从已验证 model cards 中筛选能力匹配者。
3. 比较费用、排队、失败率、输出质量和可恢复性。
4. 对关键镜头先做单镜试产。
5. 以真实输出而不是营销能力作为项目内路由依据。

## 起始候选而非永久排名

- Seedance 系列：多模态参考和多镜头编排的候选；具体版本和入口参数必须重查。
- MiniMax H3：短时视频、参考图 / 音频、原生音轨的候选；时长与参考限制按入口核实。
- Wan 系列：本地 / 云端可部署路线和较长段落的候选；硬件、工作流与权重许可需核实。
- Kling 系列：元素绑定、镜头编排和编辑能力的候选；实际入口 schema 优先。
- ComfyUI：工作流执行层，不是单一模型；节点、权重、显存和依赖按 workflow manifest 管理。
- 图像模型：用于角色 / 场景 / 道具母版和关键帧；不要让一张图同时承担身份、姿势、光线和镜头所有控制职责。

## 路由禁令

- 不从旧截图或其他聚合平台推断当前 API 参数。
- 不把同系列模型视为相同能力。
- 不默认首尾帧模式可与参考视频模式共存。
- 不假设模型支持指定时长、画幅或原生对白。
- 不将试产结果外推成质量保证。
- 模型能力不符时，缩短 / 拆分镜头或换已验证路线；不得静默丢失用户要求。
